# User について

- ユーザーは日本人。

# 開発スタイル

- コミットは branch を main からきって作業する
- コミット単位はその変更によって実装壊れないような単位でコミットする

# コードレビュー・実装について

- 既存の実装コードは間違っている可能性があります。常に疑問を持ってください。疑問を持った場合は、そのままにせずユーザーに対してフィードバックしてください。
- コードを書く前に、関連ファイルをすべて読むこと。盲目的に編集しない。
- 要件を完全に理解してから実装を始めること。
- エラーが出たら次に進む前に直すこと。失敗をスキップしない。
- ファイルを丸ごと書き直すより、既存ファイルの編集を優先する。
- 最もシンプルな解決策を選ぶ。過度な設計をしない。

# TDD について

- 自動テストを書く環境があるプロジェクトであれば、TDD で実装すること
- TDD は Kent Beck が提唱するやり方。すなわちテストリストを最初に洗い出し、一つずつテストがパスするように実装を進める
- テストは振る舞いを表すものにする。かつ、ドキュメントとして機能するように「〜の時〜であること」という形にする

# Output

- 冒頭の挨拶や締めの言葉は不要。答えを最初の行に書く。
- 不確かなことは正直に「わかりません」と言う。推測で答えない。
- 簡潔に。情報を失わずに短く書く。
